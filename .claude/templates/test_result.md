## 완료 기준 검증

spec.md의 AC(`F1-1`, `F1-2`, ... / 공통 `C1`, `C2`, ...) 전부를 빠짐없이 한 행씩 적는다.
"비고"에는 FAIL일 때만 실패 유형을 `[구현]` 또는 `[설계]`로 표시한다 — `[구현]`은 코드/테스트가
아직 기준을 못 채운 경우(implementer가 다시 작업), `[설계]`는 plan.md의 구현 방법 자체가
잘못됐거나(아래 architecture 재검증 포함) backlog 의도와 어긋난 경우(designer가 다시 작업)다.

## architecture 재검증

plan.md "영향 레이어/파일" 표가 `architecture` 스킬의 레이어 표·의존성 방향과 실제
코드 기준으로 맞는지 확인한다 — designer는 이 판단을 하지만 implementer는 재검토하지
않으므로, 레이어 판단 오류가 구현 단계까지 그대로 흘러갔을 위험을 여기서 걸러내는 게
목적이다.

- [ ] plan.md에 적힌 레이어/파일이 실제 코드 위치와 일치한다
- [ ] 역방향 참조(하위 레이어가 상위 레이어를 참조)가 생기지 않았다
- [ ] plan.md/task.md 범위에 없는 파일이 추가로 수정되지 않았다 (범위 이탈 여부)

불일치가 있으면 여기에 구체적으로 적고, 관련된 AC를 위 표에서 `[설계]` FAIL로 표시한다.
